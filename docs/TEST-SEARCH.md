# Local test search and permission groups

The local SOSL path implements test fixed results, not a production text-search index. `Test.setFixedSearchResults(List<Id>)` snapshots a bounded ID list. Subsequent searches resolve existing records of each `RETURNING` type, apply the real filters/order/limits, project selected fields and relationships, and preserve one result list per requested object. Without fixed results, test searches return empty lists while still validating fields and binds. Search terms are evaluated and type-checked but do not filter the fixed IDs, as described in the [Salesforce Apex Developer Guide](https://developer.salesforce.com/docs/atlas.en-us.apexcode.meta/apexcode/apex_testing_SOSL.htm).

The subset supports static `FIND` expressions, `IN ... FIELDS`, and explicit returning projections with supported SOQL predicates. It counts SOSL separately from SOQL, resets the test limit frame at `startTest`, and blocks uncatchably after 20 searches. The supported result/fixed-ID bound is 2,000. Unknown clauses, dynamic Search APIs, unqualified asynchronous fixed-result inheritance, and ContentDocument/ContentNote index mapping block explicitly. Returned values are real projected records, not fabricated results keyed by a test name.

Row access follows the active class sharing context; API 67+ also uses the explicit local user policy by default. Missing policy information blocks. The access model remains synthetic and requires independent Salesforce qualification.

`Test.calculatePermissionSetGroup(Id)` validates the actual group's members against loaded permission metadata, then marks the group updated so access resolution can union those members' grants. Membership DML invalidates the group. Adding/removing a member changes subsequent permissions; this is not a status-only no-op. Missing or unresolved security metadata blocks calculation. Salesforce documents recalculation and assignment restrictions in [Permission Set Group Status and Recalculation](https://help.salesforce.com/s/articleView?id=platform.perm_set_groups_status_recalc.htm&language=en_US&type=5) and the [test calculation release note](https://help.salesforce.com/s/articleView?id=release-notes.rm_forcecom_test_permission_set_groups_apex.htm&language=en_US&release=236&type=5).

Independent regressions exercise changed fixed IDs, nonmatching search terms, actual WHERE/LIMIT effects, relationship projections, empty-table validation, separate query counts, governor catch attempts, member grants and permission removal. The pinned upstream corpus is left unchanged.
